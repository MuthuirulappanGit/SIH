# WattWise MVP — Deployment Kit

## What this package is

This is a deployment-ready source package based on the supplied WattWise MVP.
It contains the application source plus Docker and hosting configuration.

## IMPORTANT

The original local `.env` file was intentionally NOT included.
Never upload real passwords, JWT secrets, device keys, or other secrets to GitHub.

The included `.env.production.example` is only a template.

## Recommended deployment architecture

WattWise is a full-stack application:

Browser
  -> Express/Node server
  -> SQLite database
  -> ESP32 devices

The Express server serves the built React/Vite frontend and the API from the same port.

Therefore, deploy WattWise as ONE Node/Docker web service rather than deploying the frontend as a separate static-only site.

## Local verification before deployment

Use Node.js 20.x for this project because `better-sqlite3` is a native Node module.

PowerShell:

    cd "C:\path\to\WattWise MVP"
    node -v
    npm -v
    npm ci
    npm rebuild better-sqlite3
    npm run build
    npm start

Expected:

    WattWise API listening on 4000

Then open:

    http://localhost:4000

Health check:

    http://localhost:4000/api/health

## Login

The supplied project is configured to use:

    Username: Admin123
    Password: set by ADMIN_PASSWORD

For deployment, DO NOT reuse a simple/demo password. Set a strong `ADMIN_PASSWORD` in the hosting provider.

## Environment variables

Set these in the hosting provider:

    PORT=4000
    DATABASE_PATH=/app/data/wattwise.db
    JWT_SECRET=<long random secret>
    ADMIN_USERNAME=Admin123
    ADMIN_PASSWORD=<strong password>
    DEVICE_API_SECRET=<long random secret>
    CORS_ORIGIN=https://<your-public-domain>
    NODE_ENV=production

## Render / Docker deployment

This package includes:

    Dockerfile
    render.yaml
    .dockerignore
    .env.production.example

General process:

1. Put this project in a GitHub repository.
2. Do NOT commit `.env`.
3. Create a Docker-based Web Service on your hosting provider.
4. Use the included `Dockerfile`.
5. Set the production environment variables.
6. Deploy.
7. Open the public URL.
8. Test `/api/health`.
9. Test administrator login.
10. Test the dashboard and hardware pages.

## SQLite persistence warning

The current WattWise MVP uses SQLite (`better-sqlite3`).

A container filesystem may be temporary depending on the hosting provider. If the service is restarted/redeployed without persistent storage, local SQLite data can be lost.

For a hackathon/demo prototype this may be acceptable, but for a real production system use persistent storage or migrate the database layer to a managed database.

Do NOT assume a free hosting tier provides durable SQLite storage.

## ESP32 after deployment

Once the website/backend has a public HTTPS URL, the ESP32 must send telemetry to:

    https://YOUR_DOMAIN/api/esp32/data

Use:

    Content-Type: application/json
    X-Device-Key: <device key generated by WattWise>

The device payload must contain the registered device ID and assigned room ID.

## Important hardware note

Do not expose a device API key in frontend code, screenshots, GitHub repositories, or public documentation.

## Zero Fake Data behavior

The application is designed to show zero/waiting values when no fresh hardware telemetry is available. Do not seed fake electricity readings for a live demonstration if you want to preserve the project's zero-fake-data behavior.

## Current known local issue

If you see:

    NODE_MODULE_VERSION 115
    this version of Node.js requires NODE_MODULE_VERSION 137

you are running Node 24 with a `better-sqlite3` binary built for an older Node version.

Use Node 20 for this project and run:

    npm rebuild better-sqlite3

Then run the build again.
